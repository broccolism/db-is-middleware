# 사용자 인터페이스 용어 디버깅

**한 줄로**: UI 설계 단원의 일부 문장은 "UI 자체"와 "UI를 개발하는 시스템"을 섞어 말해서 헷갈리기 쉽다.

---

## 📌 3줄 요약

- **시험에선**: UI의 세 가지 분야는 물리적 제어, 디자인, 기능으로 외운다.
- **이해할 땐**: UI 설계는 예쁜 화면만이 아니라 실제 시스템 구조, 데이터 흐름, 상태 제약과 맞아야 한다.
- **주의할 점**: "사용자 인터페이스 개발 시스템의 기능"이라는 표현은 실제로는 UI 개발 도구보다 UI 자체가 갖춰야 할 기능에 가깝게 쓰인다.

---

## 사용자 인터페이스의 세 가지 분야

사용자 인터페이스의 세 가지 분야는 보통 다음처럼 정리한다.

| 분야 | 의미 | 예시 |
| --- | --- | --- |
| 물리적 제어 분야 | 사용자가 시스템을 조작하는 물리적 수단 | 키보드, 마우스, 터치스크린, 버튼, 리모컨 |
| 디자인 분야 | 화면에 정보와 콘텐츠를 어떻게 보여줄지 구성 | 화면 레이아웃, 색상, 아이콘, 메뉴 배치, 글꼴 |
| 기능 분야 | 사용자가 편리하게 사용할 수 있도록 돕는 기능 | 검색, 자동완성, 오류 메시지, 도움말, 단축키 |

예를 들어 키오스크를 보면 세 분야가 한꺼번에 보인다.

```text
물리적 제어: 터치스크린을 누른다
디자인: 메뉴 버튼이 화면에 배치된다
기능: 잘못 누르면 이전 단계로 돌아가거나 도움말을 보여준다
```

시험용으로는 다음 한 줄이면 충분하다.

> 사용자 인터페이스의 세 가지 분야는 물리적 제어 분야, 디자인 분야, 기능 분야이다.

---

## UI 설계를 위해 소프트웨어 아키텍처를 알아야 한다는 말

교재 문장:

> UI 설계를 위해서는 소프트웨어 아키텍처를 반드시 숙지해야 한다.

이 문장은 디자이너가 서버 코드, DB 설계, 네트워크 프로토콜까지 모두 알아야 한다는 뜻은 아니다.

더 정확한 의미는 다음에 가깝다.

> UI는 실제 시스템 구조, 데이터 흐름, 기능 제약과 맞게 설계되어야 한다.

예를 들어 UI에 `주문 취소` 버튼이 있다고 하자. 겉으로는 버튼 하나지만 실제 시스템에서는 여러 조건이 따라붙는다.

- 이미 배송 시작 상태라면 취소 불가
- 결제 취소 API 호출 필요
- 재고 복구 필요
- 쿠폰 사용 내역 복구 필요
- 주문 상태 변경 필요

이 구조를 모르면 UI가 아무 때나 주문을 취소할 수 있는 것처럼 보일 수 있다. 그러면 사용자가 보는 화면과 실제 시스템 동작이 어긋난다.

또 `실시간 재고`처럼 보이는 UI를 만들고 싶어도, 실제 시스템이 10분마다 재고를 갱신한다면 UI에서 실시간처럼 표현하는 것은 위험하다.

따라서 UI 설계자가 알아야 하는 것은 구현 세부가 아니라 다음과 같은 시스템 제약이다.

- 어떤 기능이 가능한가
- 어떤 데이터가 어디서 오는가
- 어떤 처리는 시간이 걸리는가
- 어떤 상태에서는 버튼이 비활성화되어야 하는가
- 어떤 오류가 발생할 수 있는가

정리하면, UI 설계자는 개발자처럼 내부 구현을 모두 알 필요는 없지만 **UI가 기대는 시스템 구조와 제약은 이해해야 한다**.

---

## "사용자 인터페이스 개발 시스템"이라는 표현의 문제

교재 문장:

> 사용자 인터페이스 개발 시스템이 가져야 할 기능

이 표현은 꽤 애매하다. 말 그대로 해석하면 UI 개발 시스템은 UI를 만들기 위한 도구나 환경처럼 들린다.

예를 들면 다음이 떠오른다.

- Figma
- Storybook
- React, Vue 같은 UI 프레임워크
- 디자인 시스템
- 컴포넌트 라이브러리
- UI 빌더

그런데 교재가 이 항목에서 말하는 내용은 보통 이런 개발 도구의 기능이 아니다. 실제로는 **개발된 사용자 인터페이스가 갖춰야 할 기능**에 가깝다.

대표적으로 다음 세 가지가 나온다.

| 기능 | 실제 의미 | 예시 |
| --- | --- | --- |
| 사용자 입력 검증 | 사용자가 입력한 값이 올바른지 확인 | 필수 입력 누락, 이메일 형식, 비밀번호 조건 검사 |
| 에러 처리와 복구 | 오류가 발생했을 때 안내하고 회복할 수 있게 함 | 오류 메시지, 다시 시도, 임시 저장 복구 |
| 도움과 프롬프트 제공 | 사용자가 다음에 무엇을 해야 할지 안내 | 도움말, 툴팁, 입력 예시, 확인 메시지 |

즉 이 문장을 더 정확히 고치면 다음에 가깝다.

> 사용자 인터페이스는 입력 검증, 오류 처리, 도움과 안내 기능을 제공해야 한다.

또는:

> 사용자 인터페이스를 개발할 때는 입력 검증, 오류 처리, 도움말 제공을 고려해야 한다.

---

## 왜 이 표현이 헷갈릴까?

문제는 "개발 시스템"이라는 말이 두 의미를 모두 떠올리게 한다는 점이다.

| 표현 | 자연스러운 해석 | 교재에서 실제로 말하는 내용 |
| --- | --- | --- |
| UI 개발 시스템 | UI를 만드는 도구, 프레임워크, 개발 환경 | UI 자체가 사용자에게 제공해야 할 기능 |
| 입력 검증 | UI 개발 도구의 기능처럼 보일 수 있음 | 완성된 UI가 사용자의 입력을 검사하는 기능 |
| 오류 처리 | 개발 시스템 내부 오류 처리처럼 보일 수 있음 | 사용자가 오류 상황에서 회복하도록 돕는 기능 |

그래서 이 표현은 다음처럼 받아들이는 편이 안전하다.

> "사용자 인터페이스 개발 시스템의 기능"은 엄밀한 도구 설명이라기보다, UI를 개발할 때 UI에 반영해야 할 사용자 지원 기능을 말한다.

---

## 🎯 정처기 문제 풀 때 꿀팁

**키워드 매칭 전략**:

- `물리적 제어`, `디자인`, `기능` -> 사용자 인터페이스의 세 가지 분야
- `키보드`, `마우스`, `터치스크린` -> 물리적 제어 분야
- `레이아웃`, `색상`, `아이콘`, `메뉴 배치` -> 디자인 분야
- `검색`, `자동완성`, `도움말`, `오류 메시지` -> 기능 분야
- `입력 검증`, `에러 처리`, `도움/프롬프트` -> UI가 갖춰야 할 사용자 지원 기능

**함정 주의**:

- "UI 개발 시스템"을 현대적인 UI 개발 도구로만 해석하면 교재 설명이 이상해진다.
- 시험에서는 교재 표현을 따르되, 이해할 때는 "UI 자체가 갖춰야 할 기능"으로 읽는 편이 낫다.

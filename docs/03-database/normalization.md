# 정규화와 함수 종속

**한 줄로**: 정규화는 속성 사이의 함수 종속을 보고, 한 테이블에 섞이면 안 되는 사실을 분리하는 과정이다.

교재의 정규형 설명은 보통 암기하기 좋게 줄여서 나온다. 하지만 3NF와 BCNF는 후보키, 프라임 속성, 슈퍼키를 구분하지 않으면 문장이 서로 같은 말처럼 보이다가 갑자기 어긋난다.

## 기본 용어

| 용어 | 뜻 |
| --- | --- |
| 함수 종속 `X -> A` | `X` 값이 정해지면 `A` 값이 하나로 정해진다는 뜻 |
| 슈퍼키 | 한 튜플을 유일하게 식별할 수 있는 속성 집합 |
| 후보키 | 최소성을 만족하는 슈퍼키 |
| 프라임 속성 | 어떤 후보키에라도 포함되는 속성 |
| 비프라임 속성 | 어떤 후보키에도 포함되지 않는 속성 |

## 2NF

2NF는 1NF를 만족하면서, 비프라임 속성이 후보키의 일부에만 종속되지 않는 정규형이다.

쉽게 말하면 다음 문제를 제거한다.

```text
복합 후보키 = (A, B)
A -> C
```

`C`가 비프라임 속성이라면 `C`는 후보키 전체 `(A, B)`가 아니라 일부 `A`에만 의존한다. 이것이 부분 함수 종속이다.

2NF의 감각은 다음과 같다.

```text
2NF = 복합 키의 일부만 보고 알 수 있는 일반 속성을 빼낸다.
```

## 3NF의 두 표현

교재식 표현은 보통 다음처럼 나온다.

> 3NF는 2NF이면서, PK가 아닌 모든 속성이 PK에 대해 이행적 종속을 만족하지 않는 정규형이다.

하지만 엄밀한 3NF 정의는 다음이다.

> 릴레이션 `R`의 모든 비자명 함수 종속 `X -> A`에 대해, `X`가 슈퍼키이거나 `A`가 프라임 속성이면 3NF이다.

두 표현은 비슷하지만 완전히 같은 문장은 아니다. 교재식 표현은 보통 **후보키가 사실상 PK 하나뿐인 상황**을 전제로 한 축약 설명이다.

### 단일 후보키 조건에서의 동치

다음 조건을 둔다.

```text
K = 유일한 후보키이자 PK
R은 2NF를 만족한다
A는 비프라임 속성이다
```

이때 교재식 위반 조건과 엄밀 정의의 위반 조건은 같은 구조를 가리킨다.

#### 교재식 위반에서 엄밀 정의 위반으로

교재식 3NF 위반은 다음 구조다.

```text
K -> X
X -> A
X는 K의 슈퍼키가 아님
A는 비프라임 속성
```

즉 `A`는 `K`에 직접만 의존하는 것이 아니라 `X`를 거쳐 의존한다.

```text
K -> X -> A
```

이때 함수 종속 `X -> A`를 엄밀한 3NF 정의로 검사한다.

```text
X는 슈퍼키가 아니다.
A는 프라임 속성이 아니다.
```

엄밀한 3NF 조건인 “`X`가 슈퍼키이거나 `A`가 프라임 속성”을 둘 다 만족하지 못한다. 따라서 엄밀한 정의에서도 3NF 위반이다.

#### 엄밀 정의 위반에서 교재식 위반으로

엄밀한 3NF 위반은 어떤 비자명 함수 종속 `X -> A`가 있을 때 다음이 성립하는 경우다.

```text
X는 슈퍼키가 아니다
A는 프라임 속성이 아니다
```

지금은 후보키가 `K` 하나뿐이므로 `K`는 모든 속성을 결정한다.

```text
K -> X
K -> A
```

그리고 이미 `X -> A`가 있다.

```text
K -> X -> A
```

또 `X`는 슈퍼키가 아니므로 `X`만으로 전체 튜플을 식별하지 못한다. 즉 `A`는 `K`에서 `X`를 거쳐 결정되는 비프라임 속성이다. 이것이 교재식 표현의 이행적 종속 구조다.

따라서 단일 후보키를 전제로 하면 다음 두 표현은 같은 위반 구조를 잡는다.

```text
교재식: 비키 속성이 PK에 이행 종속되면 안 된다.
엄밀식: X -> A에서 X가 슈퍼키가 아니고 A도 프라임 속성이 아니면 안 된다.
```

### 왜 완전히 같은 말은 아닌가

엄밀한 3NF는 후보키가 여러 개인 경우까지 다룬다. 이때 어떤 속성은 현재 PK에는 들어가지 않지만 다른 후보키에는 들어갈 수 있다. 그래서 `PK가 아닌 속성`이라는 표현보다 `프라임 속성`이라는 표현이 정확하다.

또 엄밀한 3NF는 다음 예외를 허용한다.

```text
X -> A
X는 슈퍼키가 아님
A는 프라임 속성
```

오른쪽 `A`가 후보키의 일부라면 3NF는 허용할 수 있다. 반면 BCNF는 이 예외를 허용하지 않는다.

```text
3NF: X가 슈퍼키이거나 A가 프라임 속성이면 허용
BCNF: X는 무조건 슈퍼키여야 함
```

### 3NF는 왜 프라임 속성을 예외로 허용하나

3NF의 목적은 단순히 중복을 끝까지 없애는 것이 아니다. 3NF는 다음 세 가지를 함께 노린다.

```text
1. 데이터 중복과 갱신 이상을 줄인다.
2. 분해했을 때 정보가 사라지지 않게 한다. 즉 무손실 분해를 원한다.
3. 원래 릴레이션에서 성립하던 중요한 함수 종속을 보존한다.
```

여기서 BCNF와 갈라지는 지점은 **종속성 보존**이다.

문제의 예외 구조는 다음과 같다.

```text
X -> A
X는 슈퍼키가 아님
A는 프라임 속성
```

`X`가 슈퍼키가 아니므로 이 함수 종속은 분명히 찝찝하다. 그래서 BCNF는 이 구조를 허용하지 않는다. 하지만 `A`가 프라임 속성이라는 것은 `A`가 어떤 후보키의 일부라는 뜻이다. 즉 `A`는 단순한 설명 속성이 아니라 튜플 식별 구조에 참여하는 속성이다.

이런 경우까지 무조건 분해하면 중복은 더 줄어들 수 있지만, 원래 함수 종속을 각 분해된 릴레이션 안에서 직접 검사하지 못할 수 있다. 다시 말해 조인을 해야만 원래 종속을 확인할 수 있는 상태가 될 수 있다.

그래서 3NF는 다음처럼 타협한다.

```text
비프라임 속성이 키 아닌 속성에 딸려오는 전형적인 이행 종속은 제거한다.
하지만 오른쪽이 프라임 속성인 종속은, 종속성 보존을 위해 예외적으로 허용한다.
```

따라서 3NF는 “느슨한 BCNF”라기보다 다음에 가깝다.

```text
3NF = 이상 현상을 줄이되, 무손실 분해와 종속성 보존을 함께 챙기는 정규형
BCNF = 모든 결정자가 슈퍼키가 되도록 더 엄격하게 밀어붙이는 정규형
```

## 3NF와 BCNF의 차이

3NF와 BCNF의 차이는 “오른쪽이 프라임 속성일 때 봐주느냐”에 있다.

| 정규형 | 조건 | 예외 |
| --- | --- | --- |
| 3NF | `X -> A`에서 `X`가 슈퍼키이거나 `A`가 프라임 속성 | 있음 |
| BCNF | `X -> A`에서 `X`가 슈퍼키 | 없음 |

따라서 BCNF는 3NF보다 더 엄격하다.

```text
3NF = 결정자가 슈퍼키가 아니어도, 결정되는 속성이 프라임 속성이면 허용
BCNF = 결정자는 언제나 슈퍼키여야 함
```

## 빠른 요약

```text
2NF
= 복합 후보키의 일부에만 의존하는 비프라임 속성 제거

3NF, 교재식
= 비키 속성이 PK에 이행 종속되는 구조 제거

3NF, 엄밀식
= 모든 X -> A에 대해 X가 슈퍼키이거나 A가 프라임 속성이어야 함

BCNF
= 모든 X -> A에 대해 X가 슈퍼키여야 함
```

시험용으로는 다음처럼 기억하면 좋다.

```text
2NF = PK 일부 의존 제거
3NF = 키 아닌 것끼리의 의존 제거, 단 엄밀하게는 프라임 속성 예외가 있음
BCNF = 모든 결정자는 후보키
```

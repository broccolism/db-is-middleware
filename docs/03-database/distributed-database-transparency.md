# 분산 데이터베이스의 투명성

**한 줄로**: 분산 데이터베이스의 투명성은 내부가 훤히 보인다는 뜻이 아니라, 분산으로 인한 차이와 복잡성이 투명해져서 사용자에게 보이지 않는다는 뜻이다.

교재에서 분산 데이터베이스의 목표로 `투명성`이 나오면 말이 이상하게 느껴질 수 있다. 한국어에서 투명하다는 말은 보통 “속이 보인다”는 뜻에 가깝기 때문이다.

하지만 컴퓨터공학에서 `transparency`는 자주 다음 뜻으로 쓰인다.

```text
사용자나 프로그램이 내부 복잡성을 의식하지 않아도 되는 성질
```

즉 여기서 투명성은 다음 뜻이 아니다.

```text
내부 위치, 복제 상태, 분할 구조가 다 보인다.
```

오히려 다음 뜻에 가깝다.

```text
내부 위치, 복제 상태, 분할 구조의 차이가 투명해져서 사용자에게 보이지 않는다.
```

## 왜 “투명성”인가

분산 데이터베이스는 실제로 여러 사이트에 데이터가 나뉘어 있을 수 있다.

```text
서울 DB 서버
부산 DB 서버
도쿄 DB 서버
```

하지만 사용자는 보통 이런 물리적 위치를 직접 알고 싶어 하지 않는다. 사용자는 논리적인 이름으로 접근하고 싶다.

```sql
SELECT * FROM 고객;
```

이때 사용자는 `고객` 데이터가 서울에 있는지, 부산에 있는지, 여러 곳에 복제되어 있는지 몰라도 된다. 분산되어 있다는 차이가 투명해져서 사용자에게 보이지 않는다.

그래서 “위치가 투명하다”는 말은 다음 뜻이 아니다.

```text
위치가 훤히 보인다.
```

정확한 감각은 다음이다.

```text
위치 차이가 투명해져서 없는 것처럼 사용할 수 있다.
```

따라서 한국어 감각으로는 “위치가 불투명한 것 아닌가?”라는 의문이 자연스럽다. 실제 구현 위치는 사용자에게 감춰진다. 다만 CS 용어로는 그 감춰짐을 “위치 차이가 투명해졌다”고 표현한다.

## 주요 투명성

| 투명성 | 뜻 | 사용자가 몰라도 되는 것 |
| --- | --- | --- |
| 위치 투명성 | 데이터가 어느 사이트에 저장되어 있는지 몰라도 접근할 수 있음 | 물리적 저장 위치 |
| 중복 투명성 | 같은 데이터가 여러 곳에 복제되어 있어도 하나처럼 사용할 수 있음 | 복제본의 존재와 선택 |
| 분할 투명성 | 테이블이 여러 조각으로 나뉘어 있어도 원래 테이블처럼 접근할 수 있음 | 수평/수직 분할 구조 |
| 장애 투명성 | 일부 사이트나 통신에 장애가 나도 가능한 한 사용자는 계속 사용할 수 있음 | 장애 발생과 복구 절차 |
| 병행 투명성 | 여러 사용자가 동시에 접근해도 일관성이 유지됨 | 동시성 제어 과정 |

## 위치 투명성

위치 투명성은 데이터가 어느 노드에 있는지 몰라도 논리 명칭으로 접근할 수 있는 성질이다.

```text
사용자 관점: 고객 테이블 조회
시스템 내부: 서울 고객 조각 + 부산 고객 조각 + 복제본 선택
```

사용자는 다음처럼 생각한다.

```text
고객 데이터를 조회한다.
```

시스템은 내부적으로 다음을 처리한다.

```text
어느 사이트에 접속할지 결정한다.
필요하면 여러 사이트의 결과를 합친다.
복제본이 있다면 적절한 복제본을 선택한다.
```

사용자는 이 과정을 몰라도 된다. 그래서 위치 차이가 투명해져서 사용자에게 보이지 않는다.

## 중복 투명성

중복 투명성은 같은 데이터가 여러 곳에 복제되어 있어도 사용자가 복제 여부를 신경 쓰지 않아도 되는 성질이다.

```text
고객 데이터 복제본 A
고객 데이터 복제본 B
고객 데이터 복제본 C
```

사용자는 어느 복제본을 읽을지 직접 고르지 않는다. 시스템이 가까운 복제본, 살아 있는 복제본, 최신 복제본 등을 선택한다.

핵심은 다음이다.

```text
복제되어 있지만 하나의 데이터처럼 보인다.
```

## 분할 투명성

분할 투명성은 하나의 논리 테이블이 여러 조각으로 나뉘어 저장되어 있어도 사용자가 원래 테이블처럼 사용할 수 있는 성질이다.

수평 분할의 예:

```text
고객_서울 = 서울 고객 행들
고객_부산 = 부산 고객 행들
```

수직 분할의 예:

```text
고객_기본정보 = 고객번호, 이름
고객_연락처 = 고객번호, 전화번호, 이메일
```

사용자는 이런 조각 이름을 직접 알 필요 없이 다음처럼 접근한다.

```sql
SELECT * FROM 고객;
```

시스템은 내부적으로 분할된 조각을 찾아 합친다.

## 투명성과 불투명성의 말장난

한국어로는 다음 질문이 충분히 타당하다.

```text
위치를 알 필요가 없다면 위치는 오히려 불투명한 것 아닌가?
```

맞다. 구현 세부사항 자체는 사용자에게 불투명해진다. 하지만 CS에서 말하는 투명성은 “내부가 보인다”가 아니라 “내부 차이가 투명해져서 사용 경험에 드러나지 않는다”는 뜻이다.

비슷한 표현이 다른 곳에도 있다.

| 표현 | 뜻 |
| --- | --- |
| transparent proxy | 사용자가 프록시 존재를 의식하지 않아도 동작하는 프록시 |
| transparent compression | 사용자가 압축/해제를 직접 신경 쓰지 않아도 자동 처리되는 압축 |
| transparent caching | 사용자가 캐시 존재를 몰라도 성능 향상을 받는 캐시 |

모두 내부 구조가 보인다는 뜻이 아니라, 내부 처리를 사용자가 신경 쓰지 않아도 된다는 뜻이다.

## 시험용 정리

```text
분산 데이터베이스의 투명성
= 데이터가 여러 곳에 분산, 복제, 분할되어 있어도
  사용자는 하나의 데이터베이스처럼 사용할 수 있게 하는 성질
```

짧게 외우면 다음이 좋다.

```text
투명성 = 내부가 보인다 X
투명성 = 내부 차이가 투명해져서 안 보인다 O
```

위치 투명성은 특히 이렇게 잡으면 된다.

```text
위치 투명성
= 데이터의 실제 저장 위치를 몰라도 논리 명칭으로 접근할 수 있는 성질
```

# UML 다이어그램 예제 모음

**한 줄로**: UML 다이어그램은 같은 시스템을 보더라도 “시간 흐름”, “정적 구조”, “사용자 기능” 중 무엇을 보느냐에 따라 완전히 다른 그림이 된다.

일반적인 교재 예제는 너무 작거나 추상적인 경우가 많다. 그래서 여기서는 **온라인 쇼핑몰 주문**이라는 같은 상황을 세 가지 UML 다이어그램으로 나란히 둔다.

---

## 순차 다이어그램

순차 다이어그램은 객체들이 주고받는 메시지를 시간 순서대로 보여준다. 시간은 위에서 아래로 흐른다.

![온라인 주문 결제 순차 다이어그램](/img/image-repository/uml-sequence-order.svg)

이 그림에서 볼 것:

- 고객이 쇼핑몰 화면에 주문을 요청한다.
- 쇼핑몰 화면은 주문 서비스에 `createOrder()`를 호출한다.
- 주문 서비스는 재고 DB를 조회하고, 결제 API에 승인 요청을 보낸다.
- 응답 메시지는 점선으로 돌아온다.

시험용으로는 이렇게 잡으면 된다.

> 순차 다이어그램 = 객체 사이의 메시지 전달 순서

---

## 클래스 다이어그램

클래스 다이어그램은 시스템의 정적인 구조를 보여준다. 흐름이 아니라 클래스, 속성, 메서드, 관계를 본다.

![주문 도메인 클래스 다이어그램](/img/image-repository/uml-class-order.svg)

이 그림에서 볼 것:

- `Customer`와 `Order`는 연관 관계이다.
- `Order`와 `OrderItem`은 합성 관계이다. 주문이 사라지면 주문 항목도 함께 사라지는 강한 전체-부분 관계로 본다.
- `OrderItem`은 `Product`와 연결된다.
- `Order`는 결제를 위해 `PaymentService`에 의존한다.
- `KakaoPayment`는 `PaymentService` 인터페이스를 실체화한다.

시험용으로는 이렇게 잡으면 된다.

> 클래스 다이어그램 = 클래스의 정적 구조와 관계

---

## 유스케이스 다이어그램

유스케이스 다이어그램은 액터가 시스템으로 무엇을 할 수 있는지 보여준다.

![온라인 쇼핑몰 유스케이스 다이어그램](/img/image-repository/uml-usecase-shopping.svg)

이 그림에서 볼 것:

- 고객은 상품 조회와 상품 주문 기능에 참여한다.
- 회원은 주문 취소 기능에 참여한다.
- 상품 주문은 로그인과 결제하기를 항상 포함한다.
- 쿠폰 적용은 상품 주문을 조건부로 확장한다.
- 회원은 고객의 특수한 액터이다.
- 상품 관리는 관리 업무의 특수한 유스케이스이다.

시험용으로는 이렇게 잡으면 된다.

> 유스케이스 다이어그램 = 누가 시스템으로 무엇을 할 수 있는가

---

## 세 다이어그램의 차이

| 다이어그램 | 핵심 질문 | 주로 보는 것 |
| --- | --- | --- |
| 순차 다이어그램 | 누가 누구에게 어떤 순서로 메시지를 보내는가? | 시간 흐름, 메시지 호출 |
| 클래스 다이어그램 | 어떤 클래스가 있고 서로 어떤 관계인가? | 정적 구조, 속성, 메서드, 관계 |
| 유스케이스 다이어그램 | 누가 시스템으로 무엇을 할 수 있는가? | 액터, 기능, include/extend/generalization |

한 시스템을 제대로 이해하려면 세 그림이 서로 보완되어야 한다.

```text
유스케이스 다이어그램: 사용자가 보는 기능
순차 다이어그램: 그 기능이 실행될 때의 메시지 흐름
클래스 다이어그램: 그 기능을 떠받치는 정적 구조
```
